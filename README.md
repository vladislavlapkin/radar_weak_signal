# Радар слабых сигналов — Газпромбанк.Тех 2026

Сервис находит зарождающиеся технологии в открытых источниках, отделяет их от мейнстрима,
хайпа и шума и объясняет каждое решение.

## Качество модели

5×5 стратифицированная кросс-валидация, 153 наблюдения (100 слабых сигналов + 53 негатива):

| Accuracy | Precision | Recall | F1 |
|---|---|---|---|
| 0.988 ± 0.016 | 0.991 ± 0.019 | 0.992 ± 0.018 | 0.991 ± 0.012 |

На отложенной выборке (20%) — 31 из 31 верно. Модель интерпретируема: логистическая регрессия на 16 признаках-критериях,
вклад каждого признака показан в карточке сигнала. Проверено, что модель различает классы по смыслу,
а не по стилю автора разметки (см. отчёт).

## Запуск
```bash
cp .env.example .env   # вписать YANDEX_API_KEY и YANDEX_FOLDER_ID
docker compose up --build -d
```
- Дашборд: http://localhost:3000
- API: http://localhost:8000/docs
- PostgreSQL: `localhost:5433` (пользователь `signals`)

Без ключа YandexGPT сервис работает: тексты карточек собираются из источников, и это отмечено в выдаче.

### Доступ к YandexGPT
Ключ должен принадлежать сервисному аккаунту с ролью `ai.languageModels.user` на каталог из `YANDEX_FOLDER_ID`.
Если в шапке дашборда горит «LLM офлайн» и API `/status` пишет «нет доступа (403)», выдайте роль:
консоль Yandex Cloud → каталог → «Права доступа» → «Назначить роли» → сервисный аккаунт → `ai.languageModels.user`.
API-ключ должен быть создан без ограничения области действия или с областью `yc.ai.foundationModels.execute`.
Модели: `YANDEX_LITE_MODEL=yandexgpt-lite/latest` (Lite 5), `YANDEX_PRO_MODEL=yandexgpt/rc` (Pro 5.1).

## Архитектура
| Слой | Где | Что делает |
|---|---|---|
| Запрос | `collectors/query.py` | выделяет предметную область, переводит на английский (YandexGPT → словарь → Википедия) |
| Сбор | `collectors/` | arXiv и OpenAlex за 2–3 года, русский веб, англоязычные новости; дедупликация |
| Кандидаты | `collectors/pipeline.py` | TF-IDF + KMeans: документы группируются в технологии |
| Скоринг | `scoring/`, `ml/` | правила WSS (новизна, свежесть, разнообразие, наука) + ML-модель на 16 признаках |
| Фильтр | `scoring/maturity_filter.py` | мейнстрим, хайп, шум — с причиной исключения |
| Инсайт | `analysis/cards.py`, `llm/` | описание, преимущество, кейс, обоснование; YandexGPT пишет только по источникам |
| Хранение | `db/` | запросы, документы, карточки сигналов, журнал вызовов LLM |
| API | `api/main.py` | `POST /search`, `GET /history`, `/searches/{id}`, `/signals/{id}`, `/status` |
| Интерфейс | `web/` | React-дашборд, nginx проксирует `/api` |

Разработка интерфейса без Docker: `cd web && npm install && npm run dev` (http://localhost:5173, API на :8000).

## Обучение модели
Данные: `data/dataset.xlsx` — 100 слабых сигналов от организаторов, `data/negatives.xlsx` — 53 негатива
(мейнстрим, хайп, шум), размеченных командой по протоколу на листе «Как размечали».
Датасет организаторов в репозиторий не входит — положите полученный файл в `data/dataset.xlsx`.
Обученная модель уже лежит в `ml/artifacts/model.pkl`, поэтому сервис работает сразу после клонирования.
```bash
docker compose run --rm train      # обучение в контейнере
docker compose restart api         # API подхватывает новую модель
```
Без Docker: `python -m ml.train --positives data/dataset.xlsx --negatives data/negatives.xlsx`.

Результаты в `ml/artifacts/`: `model.pkl`, `metrics.json` (accuracy/precision/recall/F1),
`report.md` (сравнение моделей, контроль стиля автора, веса признаков), `prepared_dataset.csv`
(очищенные данные с посчитанными признаками).

Прогон по новому файлу, например по закрытому датасету организаторов (если есть колонка `label`, печатает метрики):
```bash
docker compose run --rm train python -m ml.predict --data data/test.csv
```
